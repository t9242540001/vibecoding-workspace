# Real Public Browser Link Check V1

## Purpose

Link Check v1 verifies public links and contact-style links exposed by the approved public homepage route.

It runs through the existing real public browser summary workflow and stays inside the same safety envelope:

approved route/profile -> real headless browser observation -> sanitized summary -> validation/forbidden scan -> optional Qwen/DeepSeek analysis -> sanitized reports.

It is meant to answer:

- are public links discoverable from the homepage?
- do public HTTP/HTTPS links return healthy status results where checked?
- are contact-style links present?
- are private/auth/payment-like links detected and skipped?
- do the sanitized reports give a useful review signal?

## What It Checks

Link Check v1 checks:

- public link inventory from the loaded homepage;
- sanitized link label text;
- sanitized link classification;
- same-origin versus external-public classification;
- status-only checks for public-looking HTTP/HTTPS links;
- redirect count, capped by the workflow;
- contact link signals for email, phone, and messenger-style links;
- skipped private/auth-like links;
- skipped payment-like links;
- high-level console and network summary counts;
- model-readable link health signals from sanitized metadata.

The generated summary includes:

- `link_check_summary`;
- `public_link_inventory`;
- `public_link_check_results`;
- `contact_link_signals`.

## What It Does Not Check

Link Check v1 does not:

- click links in the browser;
- follow private/auth/payment/logout links;
- submit forms;
- type into fields;
- login;
- create accounts;
- trigger payment flows;
- upload files;
- send contact messages;
- collect screenshots, videos, traces, or raw HAR;
- collect raw request or response bodies;
- collect raw headers;
- collect cookies, storage state, or auth headers;
- run visual regression;
- run full product dialogue or document review scenarios.

## Safety Boundaries

Reports and artifacts must not include:

- full URLs;
- raw email addresses;
- raw phone numbers;
- query strings;
- fragments with sensitive-looking values;
- request headers;
- response headers;
- raw request bodies;
- raw response bodies;
- cookies;
- tokens;
- auth headers;
- private endpoints;
- local paths;
- personal, client, payment, or billing data.

The workflow may use short URL hashes and sanitized public domain labels. Contact links are classified and redacted, not opened.

- top skipped private/auth/payment-like links by sanitized label and type only;
- limitations.

## Known Limitations

Link Check v1 is a safe status signal, not a full navigation audit.

- It does not click links in the browser.
- It does not prove visual placement or usability.
- It does not submit forms or test contact workflows.
- Some sites reject HEAD requests; the workflow may use a status-only GET fallback without storing response bodies.
- A skipped private/auth/payment-like link is not automatically a product bug; it is a review signal.
- A broken or redirected link should be inspected by a human before product conclusions are made.
